# hxyfront-62006 珠宝镶嵌宝石分拣

源提示词编号：8

我需要一个面向珠宝镶嵌工作室的宝石分拣前端系统，可以记录宝石编号、种类、形状、克拉重量、尺寸、净度、颜色、切工、镶嵌位置和分拣状态。页面需要有分拣批次、尺寸筛选、镶嵌位置示意图、缺陷备注和按订单查看的宝石清单。

## 技术栈

React + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

开发端口：62006

## 镶嵌配石台

在分拣壳内实现的配石工作台，纯前端、无后端依赖，数据写入 `localStorage`，刷新保留。

- 预置三张订单（JD-1803 戒指 / JD-1817 吊坠 / JD-1824 排戒）与十二颗宝石，记录编号、种类、形状、克拉、尺寸、净度、切工、缺陷与镶嵌位。
- 占位门槛：仅「已分拣且缺陷已处理」的宝石可占位；未分拣、缺陷未处理的宝石在下拉中禁选。
- 跨订单唯一：同颗宝石只能待镶一处；已待镶的宝石在其它订单锁定，跨单草拟在落位校验时整单拦截。
- 原子落位：形状、尺寸区间、主/配石容量逐位校验，任一不符则整单不落，原分配不变并给出逐条原因。
- 撤回：整单撤回后宝石恢复可分配（草拟保留，便于重新落位）。
- 缺陷流转：缺陷可「处理」登记结论并留档；待镶中的宝石缺陷重新打开会暂停整单占用，全部缺陷清零后自动恢复。
- 批次切换、形状多选、尺寸区间筛选、编号/种类检索；SVG 位置示意图按戒指/吊坠/排戒绘制，点选点位与镶嵌位下拉联动。
- 全部操作写入留档日志；「恢复预置数据」可重置为初始三单十二石。

预置数据的引导路径：JD-1824 开箱可落位；JD-1817 需先处理 ST-2073 的缺陷；JD-1803 需先将 ST-2064 标记分拣。
